# Purpose

Ce document définit les règles de composition visuelle utilisées dans Cosmos Journal Pro V3.

Il ne décrit pas le style graphique (couleurs, typographie ou composants).

Il décrit la manière dont les éléments sont organisés dans l'espace afin de créer une interface cohérente, lisible et orientée vers la performance.

Toutes les futures interfaces devront respecter ces règles.

---

# Visual Philosophy

La composition visuelle doit donner une impression immédiate de :

- stabilité ;
- maîtrise ;
- précision ;
- fluidité.

L'utilisateur doit avoir le sentiment d'utiliser un véritable cockpit de trading.

Chaque élément possède une place logique.

Rien n'est décoratif.

---

# Visual Hierarchy

L'information est organisée selon quatre niveaux.

## Niveau 1

Information essentielle.

Exemples :

- Performance
- Résultat
- Décision principale

Toujours immédiatement visible.

---

## Niveau 2

Information importante.

Exemples :

- Stratégie
- Direction
- Actif
- Statistiques principales

Visible sans effort.

---

## Niveau 3

Information contextuelle.

Exemples :

- Notes
- Tags
- Liens
- Captures

Accessible rapidement sans attirer l'attention.

---

## Niveau 4

Information secondaire.

Exemples :

- Paramètres avancés
- Options
- Informations rarement consultées

Présente mais discrète.

---

# Reading Flow

Le regard doit naturellement suivre ce parcours :

Haut

↓

Centre

↓

Bas

↓

Action

Aucune rupture visuelle ne doit casser ce flux.

---

# Visual Gravity

Les éléments importants doivent naturellement attirer le regard.

Cette hiérarchie est obtenue par :

- taille ;
- contraste ;
- espacement ;
- position.

Jamais par une multiplication des couleurs.

---

# Intelligent Density

La densité visuelle dépend du contenu.

Une carte dense n'est pas un problème si son organisation reste claire.

L'espace est utilisé de manière intentionnelle.

---

# Intelligent Width

La largeur d'un panneau est définie par son contenu.

Une largeur excessive augmente inutilement les mouvements des yeux.

Le confort de lecture est prioritaire.

---

# Functional Size

Chaque composant possède une taille adaptée à sa fonction.

Les éléments critiques occupent davantage d'espace.

Les éléments secondaires restent volontairement plus compacts.

---

# Local Density

Chaque zone possède son propre rythme.

Toutes les cartes n'ont pas besoin de la même hauteur ni de la même densité.

Le contenu détermine la composition.

---

# Alignment Rules

Alignement principal :

Toujours à gauche.

Les ruptures d'alignement sont exceptionnelles.

Elles doivent toujours être justifiées par une fonction précise.

---

# White Space

Les espaces vides ne sont jamais perdus.

Ils servent à :

- séparer ;
- respirer ;
- hiérarchiser.

Réduire un espace ne signifie pas améliorer la densité.

---

# Double Viewport

Architecture officielle introduite avec le Journal.

Structure :

Viewport fixe

↓

Contenu réel

↓

Scroll unique

Objectifs :

- conserver une hauteur constante ;
- améliorer le confort de navigation ;
- éviter les doubles scrollbars.

Cette architecture devient la référence pour tous les futurs panneaux nécessitant un contenu important.

---

# Scroll Philosophy

Une seule zone de scroll doit être responsable du déplacement du contenu.

Le scroll doit être :

- fluide ;
- prévisible ;
- confortable.

Le contenu ne doit jamais sembler "bloqué" dans son conteneur.

---

# Card Composition

Chaque carte suit le même schéma.

Titre

↓

Contenu

↓

Navigation

Le titre et les boutons de navigation doivent toujours rester accessibles rapidement.

---

# Dashboard Composition

Le Dashboard privilégie :

- une lecture immédiate ;
- une vision globale ;
- un minimum de friction.

L'utilisateur doit comprendre son état de trading en quelques secondes.

---

# Analytics Composition

Analytics favorise la comparaison.

Les graphiques et indicateurs doivent rester lisibles avant d'être détaillés.

---

# Insights Composition

Les Insights mettent en avant les tendances.

Jamais les détails.

L'objectif est d'orienter la réflexion.

---

# Settings Composition

Les Paramètres privilégient la simplicité.

Les options sont regroupées par thème.

Chaque catégorie possède une hiérarchie claire.

---

# Visual Consistency

Tous les modules doivent donner l'impression d'appartenir au même produit.

Les différences de composition ne doivent exister que lorsqu'elles répondent à un besoin fonctionnel.

---

# Reference Module

Le Journal constitue la référence officielle de composition visuelle.

Tous les futurs modules devront s'en inspirer avant toute personnalisation.

---

# Design Validation Checklist

Avant de valider une interface, vérifier :

✓ La hiérarchie visuelle est-elle évidente ?

✓ Les éléments importants attirent-ils naturellement le regard ?

✓ Le parcours de lecture est-il fluide ?

✓ Les espacements sont-ils cohérents ?

✓ Une seule zone de scroll est-elle responsable du contenu ?

✓ La densité est-elle adaptée au contenu ?

✓ L'interface donne-t-elle une impression de maîtrise et de sérénité ?

Si une réponse est négative, la composition doit être revue.
