# Vision

Cosmos Journal Pro V3 est un journal de trading ultra premium conçu comme un système complet d'amélioration continue pour le trading.

Le projet est désormais entré dans une phase de **Polishing**.

L'objectif n'est plus d'ajouter de nouvelles fonctionnalités majeures, mais d'améliorer continuellement la qualité du produit.

Les axes prioritaires sont :

* Architecture
* UI
* UX
* Performance
* Cohérence
* Maintenabilité
* Qualité globale

---

# Philosophie de développement

Chaque évolution doit respecter les principes suivants :

* Simplicité
* Robustesse
* Lisibilité
* Maintenabilité

Depuis le Sprint 3, un principe directeur supplémentaire s'applique à toute
proposition UX : **Workflow First** — chaque amélioration est évaluée selon
sa contribution à l'objectif d'un trade enregistré en moins de 20-30
secondes (voir `DECISIONS_LOG.md`, D-020 et D-023).

Les micro-optimisations sans valeur mesurable sont exclues.

Toute amélioration doit produire un bénéfice concret pour le projet ou pour l'utilisateur.

#### UX-003A — Détail de l'implémentation ✅

* `index.html` : `.workspace-grid` (2 colonnes 420px/1fr) remplacé par
  `.journal-layout` (empilement vertical, Wizard puis Historique).
* `styles/layout.css` : nouvelle règle `.journal-layout` ; `#journal-panel`
  et `#history-panel` partagent une largeur de lecture commune
  (`max-width: 900px`), sans dimension figée arbitraire pour le Wizard.
* `styles/journal.css` : le panel Historique perd son ombre Cosmos Surface
  à l'état fermé (`box-shadow: none`), restaurée uniquement une fois
  déployé — il ne rivalise plus visuellement avec le Wizard.
* Aucun changement de `src/ui/journal.js` ni `src/main.js` : le mécanisme
  d'accordéon (D-025) et la persistance `historyCollapsed` (D-017) sont
  réutilisés tels quels.
* Voir `DECISIONS_LOG.md`, D-026 et D-027 pour le détail des décisions.

**Prochaine étape** : UX-003B (Wizard Premium / carousel), sans nouvelle
phase d'audit.

# Méthode de travail

Le projet suit une approche incrémentale.

Chaque ticket comprend :

1. Un audit (Livraison 1).
2. Une implémentation découpée en sous-livraisons testables (Livraison 2, 2A/2B/2C...).
3. Une validation finale (Livraison 3).
4. Une mise à jour documentaire obligatoire avant clôture.

Cette méthode est désormais officielle.
