# Purpose

Ce document référence l'ensemble des composants UI officiels de Cosmos Journal Pro V3.

Son objectif est de :

- documenter chaque composant réutilisable ;
- définir sa responsabilité ;
- éviter les implémentations dupliquées ;
- servir de référence pendant le développement des futurs modules.

Le module **Journal** constitue désormais le **Reference Module** du projet. Tout nouveau composant devra respecter les mêmes standards de qualité, d'architecture et de design.

---

# Component Philosophy

Un composant doit toujours être :

- Réutilisable
- Prévisible
- Indépendant
- Cohérent avec le Design System
- Sans logique métier complexe

La logique métier appartient à `core/`.

Les composants UI appartiennent à `ui/`.

## Double Viewport (D-041)

Architecture introduite durant le polishing du Journal.

Structure :

↓

↓

## Digital Twin Summary (`kpi--digital-twin`)

Composant officiel du Design System, rejoint le catalogue suite à DASH-001
(D-050).

**Rôle** : afficher la synthèse Réel/Théorique du Jumeau Numérique
(Document 05 §8) comme transition visuelle entre les KPI de Performance
(Niveau 1) et le panneau de Pilotage (Niveau 3).

**Layout** :
- Largeur : pleine ligne (rangée indépendante sous `.kpi-grid--primary`,
  jamais intégré à la grille 3 colonnes elle-même).
- Hauteur : fixe, dérivée du gabarit `.kpi` standard — ne varie jamais avec
  le contenu du graphique (`overflow: hidden` sur le conteneur, `height`
  fixe sur `.digital-twin-col--chart`). Aucun scroll interne autorisé.
- Organisation interne : deux colonnes flex —
  - `.digital-twin-col--info` (largeur fixe ~270px) : titre, note
    contextuelle (`#digital-twin-gap`), légende (`#digital-twin-legend`) ;
  - `.digital-twin-col--chart` (largeur fluide, `flex: 1 1 auto`) :
    graphique SVG (`#digital-twin-chart`), seul élément qui "respire"
    horizontalement.

**Usage** : réservé au Dashboard. Ne pas réutiliser tel quel pour un autre
graphique — sa contrainte de hauteur fixe est spécifique au rôle de
transition Niveau 1 → Niveau 3 du Dashboard (D-050), pas une règle générale
d'affichage de graphique.

**Justification de la hiérarchie visuelle** : plus large que les KPI
scalaires (Niveau 1) car il porte une donnée bidimensionnelle (deux courbes)
mais volontairement contraint en hauteur pour ne jamais dominer la page ni
forcer de scroll — équilibre entre Visual Gravity (mérite plus d'espace
qu'un simple chiffre) et Intelligent Density (ne doit pas alourdir l'écran).

**Statut** : Stable.
